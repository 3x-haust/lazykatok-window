# Terminal Client Scope

This note records the implementation boundary for the terminal stream MVP.

| Item | Class | Verdict | Reason | Safe alternative |
| --- | --- | --- | --- | --- |
| Private or undocumented remote KakaoTalk messaging protocols/APIs | Bright-line | Descoped | They would couple the tool to unsupported network behavior and account/session risk. | Receive through existing read-only local source adapters; send only through the official macOS app UI path. |
| Unsupported source adapters or cross-user capture | Bright-line | Descoped | A generic "adapter" must not become a way to bypass account ownership, scrape another user's session, or mutate upstream app/account state. | Use only foreground-user-authorized read-only adapters for accounts/chats the user can legitimately access. |
| Session or credential interception/reuse | Bright-line | Descoped | The terminal client should not handle KakaoTalk credentials or reusable session material. | Rely on the user's already-authorized local app data and app session. |
| KakaoTalk local DB mutation, checkpointing, vacuuming, lock manipulation, or WAL truncation | Bright-line | Descoped | The source database belongs to KakaoTalk and may contain private live state. | Open source data read-only and write only katok's own archive/index files. |
| Bulk, repetitive, piped, scheduled, or unattended sending | Bright-line | Descoped | Sending reaches other people and must remain a deliberate foreground user action. | Use one explicit `katok send` invocation or type one line and press Enter in a foreground, TTY-only `watch --reply` prompt with `--accept-use-policy` for each send. Reply mode rejects piped and redirected stdin before reading the source. |
| Remote sinks for live message contents | Gray-zone | Descoped for this MVP | Streaming private messages to webhooks/cloud services changes the privacy boundary. | Emit local stdout text/JSONL only for a local terminal or local consumer process; do not add built-in network sinks or automatic forwarding modes. |
| Detached, hidden, persistent, or auto-start monitoring | Gray-zone | Descoped for this MVP | A detached process, hidden session, login item, daemon, or other persistence would change user visibility and consent expectations. | Run `katok watch` only as a foreground command the user started in its attached terminal. |
| Image/media fetching for terminal watch | Gray-zone | Descoped for this MVP | The requested stream does not require image bytes, and media fetch has separate privacy/network behavior. | Ignore non-text bodies or surface non-sensitive placeholders already present in the read-only message record; do not print local paths, CDN URLs, tokens, or media IDs. |
| KakaoTalk UI side effects while watching | Bright-line | Descoped except explicit reply | Passive watching should not open rooms, mark messages read, move focus, send anything, create typing indicators, change presence, or reorder conversations. | Read from source adapters for display; only `watch --reply` with a user-typed line confirmed by Enter may invoke the send path after the selected chat is fixed. Blank lines and unknown slash commands never send. `--reply-no-open` permits only the non-activating Accessibility attempt to an already-open target and stops before any room open, curtain, activation/raise, focus-taking, or global-key fallback. If compose-box drain is not observed, it reports the result as unconfirmed because the text may remain in the compose box or acceptance may already have occurred; it never retries automatically, and a manual retry can duplicate a merely unobserved acceptance. Normal standalone `katok send` without `--background-only` retains its existing protected visible fallback. |
| Diagnostic logging of message bodies | Gray-zone | Descoped for this MVP | Terminal output is deliberate, but copied logs and crash/debug output can retain private text unexpectedly. | Keep status logs metadata-only and print message bodies only as the requested foreground conversation view. |
| Source deletion mirroring | Gray-zone | Descoped for this MVP | The local archive may preserve messages that later disappear from the source, and pretending otherwise would mislead users. | Document local retention and omit deletion events until an explicit deletion policy exists. |
